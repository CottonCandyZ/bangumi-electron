# 本地收藏与离线同步

已在 `codex/local-collection-sync` 实现。在线和离线统一先写 SQLite，再由主进程同步；网络失败不会回滚已经保存的操作。

## 范围

覆盖当前账号的条目收藏状态、评分、短评、标签、私密设置、逐章节点格子和批量标记，以及取消收藏和再次收藏。查看其他用户收藏仍走远端查询。角色、人物、目录收藏未接入本次同步；书籍的独立卷数/话数编辑入口和图片离线包也不在本次范围。

同步最终状态；离线期间的每个动作都会留档，但不会逐个重演成网站动态。

## 数据与代码

| 数据                                       | 实现                                                                                                                          |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 本地当前状态、已确认基线、未确认上传、冲突 | `LocalCollection`，联合主键 `user_id + subject_id`。收藏字段与章节状态按条目聚合；`collection: null` 是取消收藏，缺失表示未知 |
| 用户操作                                   | `CollectionAction`，唯一 action ID、递增 sequence、明确字段赋值、操作前快照、基线版本、确认时间                               |
| 章节最低资料                               | `CollectionEpisodeResource`，持久化 ID、标题、类型、排序及详情                                                                |
| 离线账号及清单覆盖                         | `LocalAccount`，稳定 user ID、简介、清单完整性和完整同步时间                                                                  |
| 可丢弃的资源缓存                           | 现有 Subject 等数据库缓存及 RQ persister；未缓存的资源需要联网                                                                |

主进程 `src/main/collection/repository.ts` 负责事务，`sync.ts` 负责三方合并和确认，`transport.ts` 适配 API / 网页删除，`service.ts` 负责单一队列、账号切换和退避。IPC 在 `src/main/tipc/collection.ts`。

纯领域模型在 `src/shared/collection-sync.ts`，API 数据类型移到 `src/shared/types`，Drizzle schema 不再依赖 renderer 类型。迁移 `drizzle/0006_colorful_mongoose.sql` 增加同步表并保留已有资源；`0007_open_vertigo.sql` 将旧登录时间从文本统一为毫秒时间戳，防止刷新后的 token 被旧记录遮住。

renderer 的收藏查询读取本地投影；所有已覆盖的写入口使用 `data/collection/client.ts`。一次事务追加 action、更新投影和版本、标记待同步，完成后广播查询失效。SQLite 写失败才显示保存失败。

旧的读后写缓存 hook 已拆为 `data/hooks/local-resource.ts`：本地优先、过期后台刷新、等待数据库写入、按完整 query key 发布资源；不承担用户收藏同步。SQLite bridge 不再把 SQL 失败当成空结果。

## 同步过程

1. 按账号和条目串行执行，冻结当前动作上限 N、基线 B 和本地状态 L。
2. 用绑定账号的凭证直接读取远端 R；核验 API 身份，网页取消收藏另核验 Cookie 身份。读取失败不推断远端删除。
3. 三方合并：只有一端修改则保留该端；两端相同则确认；同字段两端改成不同值则持久化冲突。
4. 无冲突时先持久化本次上传目标及读取到的远端快照，再发送最小字段 patch、必要的创建/删除和章节批次。
5. 写后回读确认，再在事务中推进基线、确认不超过 N 的动作，并重放 N 之后的新动作。
6. 超时或重启后先回读；已经达到目标则确认而不重发。部分成功按已尝试的值重新合并，不因一次 HTTP 成功就清空全部动作。

网络错误退避重试；授权错误暂停等待重新登录；参数错误保留待处理状态。重启、恢复联网、成功登录、普通本地写入会推动队列。首次建立账号清单和手动同步会完整扫描收藏分页；清单中缺失的本地条目逐条复核，不直接判定删除。普通读取只请求过期的相关条目。

章节优先缓存“在看”和已打开/已经管理的条目。未下载全部章节的历史收藏不保证每个格子均可离线操作。看完提示必须具备完整章节覆盖。`ep_status` 按上游当前行为计算全部已标记章节（包括想看和抛弃），写后采用服务端值；它与“全部看过”的判断分开。参考 [上游进度实现](https://github.com/bangumi/server/blob/master/ctrl/update_episode_progress.go)。

## 冲突与恢复语义

- 评分、短评、标签、私密、收藏类型逐字段比较；标签按集合比较，忽略顺序。短评和标签整体冲突时用户选择一端。
- 章节按 episode ID 比较；不同章节的改动可自动合并。
- 一端删除、另一端修改字段或章节时，按整条收藏解决；未知基线不伪装成默认值。
- 双方并发重新收藏但内容不同，也按整条收藏处理。
- 取消收藏留下 tombstone 和原字段/章节备份。离线移除后恢复原状可以只同步最终差异；删除已确认后再次收藏，仍恢复本地保留字段和格子。
- 上传期间继续编辑不会被旧请求确认或覆盖。弹窗提交选择时重新校验本地版本和远端，过期选择被拒绝。

统一弹窗在 `modules/common/collections/sync-dialog.tsx`，展示上次同步、本地、远端的差异，支持逐项选择或全部采用一端。关闭后冲突仍保留，只阻塞该条目。收藏侧栏右上角显示待同步数和冲突提醒，点击仅打开同步面板，在面板中点击“同步全部收藏”才触发手动同步。普通面板宽 448px，需要冲突对比时加宽至 672px；弹窗有“最近移除 · 可再次收藏”。

同步中角标显示当前阶段剩余数量，完成后隐藏，有冲突或异常时保留提醒。面板显示当前作品封面、名称、读取/上传/确认阶段，以及当前阶段实际处理数量和最近三个条目的结果；下载清单与逐条核对分别计数，“已处理”包含失败与冲突。进度是账号隔离的内存状态，切换账号清空；独立进度通知只刷新同步概览。界面只展示状态与操作，不展示本地数据库、缓存策略等实现说明。验证使用本地模拟 transport，不反复触发真实服务的全量同步。

离线身份保存于本地。网络失败和 token 失效不会自动抹去账号及其操作；主动退出停止同步，旧账号动作保留且不会混入其他账号。

## 验证与边界

`pnpm --filter bangumi-electron test:collections` 使用 Electron 的 Node 运行 SQLite 测试，避免 native addon ABI 不匹配。覆盖字段合并、生命周期冲突、事务回滚、动作去重、磁盘重启、部分写入、丢失响应、同步中编辑、过期选择、账号隔离和迁移保留资源等场景。

UI 验证使用隔离目录和虚构账号，不操作真实收藏。可用 `scripts/test/create-offline-fixture.ts` 创建全新的临时数据目录，再以 `BANGUMI_ELECTRON_USER_DATA` 指定目录启动开发版；默认数据库位置保持原样。

fixture 同时生成 `activate-offline-fixture.js`。数据库中的账号不会自动成为当前账号，必须在这个隔离实例的主窗口执行激活脚本，让 renderer localStorage 的 `current_user_id` 与测试账号一致。先通过 CDP 的 `tab`、`get url` 确认选中隔离实例主页面（不要选 `/#/command`），然后在仓库根目录执行：

```powershell
Get-Content -Raw (Join-Path $env:BANGUMI_ELECTRON_USER_DATA 'activate-offline-fixture.js') | node app/bangumi/scripts/agent-browser.mjs --cdp 9222 eval --stdin
```

页面重新加载后测试账号为 `999999991`，收藏条目为 `999999990`。只对新建的隔离 profile 执行；不要对日常使用的窗口执行。fixture 没有真实 token，网络同步需要在测试中模拟。

Drizzle 升级为 `drizzle-orm 0.45.2` 和 `drizzle-kit 0.31.10`；选择 npm stable，不引入 1.0 RC。

仍需使用指定测试账号验证真实网站的删除/恢复和写后可见性。当前自动化测试使用可控 transport；没有对真实账号发出收藏写入。

上游 [v0 OpenAPI](https://github.com/bangumi/server/blob/master/openapi/v0.yaml) 未声明收藏的条件写入版本或 If-Match。客户端能够检测读取时已经存在的冲突、保存未确认动作并核验响应，但不能严格消除“读取之后另一端修改，再被本次写入覆盖”的竞态。严格的并发无丢失保证需要服务端支持条件写入。网页取消收藏继续使用站点 hash 入口，解析失败会保留本地动作并提示重新登录。
